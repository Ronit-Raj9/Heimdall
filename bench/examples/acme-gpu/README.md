# Acme GPU example: ML-engineering tasks on a GPU

This folder is a complete Heimdall (bifrost-bench) project for a company
whose agents do ML engineering: train a model to a target, speed up a
training loop, write a faster GPU kernel. It is laid out like
[`examples/acme-design`](../acme-design/README.md); the guide is
[`docs/gpu-tasks.md`](../../docs/gpu-tasks.md). No Go code is needed.

- **One GPU per run.** Every task asks for a whole GPU (`resources.gpu` in
  `task.yaml`). A run holds it alone from before the agent starts until its
  verifier is done; the GPU is passed by UUID to the agent container and to
  the clean-room verifier only, never in privileged mode. The plan is
  refused, with the reason, on a machine without a GPU of at least 2 GiB.
- **One CUDA image** for the agent, the controls and the verifier
  (`benchmarks/acme-gpu/base/Dockerfile`): PyTorch 2.15 (CUDA 13.2) and
  Triton 3.9, which support compute capability 7.5 (Turing) and newer.
- **Graded on data the agent never sees.** A held-out set from a source only
  the verifier has, or inputs seeded from `os.urandom` at grading time.
  When a verifier times the agent's code, that code runs in a child process
  and the verifier holds the clock.
- **Hardware on the record.** Each run's `run.json` records the GPU it held,
  `gpu.samples.jsonl` holds the host-side samples taken while the agent ran,
  and the metrics `gpu_seconds`, `peak_vram_mb`, `gpu_util`, `speedup`,
  `heldout_score` and `time_to_target_s` read them.

## What is fictional

Acme, its support desk, churn model and ranking service, and every data set
here are invented for this example and generated by the scripts in it
(`verifier/tests/gen.py`, `repo/data.py`); nothing is downloaded. Everything
here was written from scratch and is MIT licensed.

```
    tasks/train-classifier/     artifact task: model.pt and model.json, scored on held-out tickets

```

## The tasks

| Task | What a correct agent does | Verifier (on the GPU, clean room) | Pass |
|---|---|---|---|
| `train-classifier` | trains `model.MLP(hidden, depth)` on `train.npz` (20,000 points) and leaves `model.pt` and `model.json` | loads the weights only (`weights_only=True`) into its own model class, scores 10,000 held-out points from a hidden generator | held-out accuracy at least 0.905 |
| `fix-slow-loop` | moves the data to the GPU once, shuffles there, drops the per-step host syncs and the per-sample `Dataset` | runs the original and the agent's `train()` in child processes on 3 fresh data seeds, alternating, timing each call itself; scores both models on held-out points drawn after every child is gone | accuracy within 1.5 points of the original's every round, median speedup at least 2.5 |
| `fused-softmax` | writes one Triton kernel that reads each row once | 10 correctness cases against a float64 softmax, then 9 alternating timed rounds of the original and the agent's kernel on 4096 x 4096 inputs, one random output of each round checked | every case correct, speedup interval lower end at least 2.0 |

Controls per task: the reference must pass three times; the empty control,
two mutants (a near miss each) and an exploit (planted reward files plus a
cheat) must fail. `requirements.md` in each verifier folder maps every
dimension to its instruction line.

## Run it

Lint, lock, admission and `gpu check` need no gateway tokens; the smoke run
needs the bench's stack running (see `examples/acme-node`) with that stack's
`.env` loaded. Every model call of the scripted controls stays inside the
stack: nothing is spent.

```sh
cd bench/examples/acme-gpu

# 1. The GPU, and whether each task fits it.
bifrost-bench gpu check -config deploy/bench.yaml -suite acme-gpu

# 2. Check, lock and admit the suite: every control runs on the GPU in the
#    agent's place and is graded by the GPU verifier (about 30 minutes on a
#    GTX 1650, most of it the timed rounds of fix-slow-loop).
bifrost-bench suite lint -config deploy/bench.yaml acme-gpu
bifrost-bench suite lock -config deploy/bench.yaml acme-gpu
bifrost-bench suite admit -config deploy/bench.yaml acme-gpu

# 3. Free run on the real GPU: oracle must verify 3 of 3, noop 0 of 3.
bifrost-bench plan experiments/gpu-smoke.yaml
BENCH_SERVER_MODE=synthetic bifrost-bench run experiments/gpu-smoke.yaml
```

The image is built by `suite admit` when it is missing (about 3 GB of
wheels to download, 9.4 GB on disk with Docker's containerd store; see the
guide). The KernelBench importer reuses it:

```sh
bifrost-bench import kernelbench -config deploy/bench.yaml -from <KernelBench clone> -suite kernelbench-l1 -ids 1,9,12,50,88
```
