# t03 requirements map

Every hidden test, the instruction sentence it checks, and what it asserts. All tests go through `ledger.load_invoices` or `python -m ledger export`.

| Hidden test | Instruction sentence | Asserts |
|---|---|---|
| `test_day_first_slash_dates_are_accepted` | Format 2 "Day first with slashes: `D/M/YYYY` ... `7/3/2026`, `07/3/2026` and `07/03/2026` all mean 7 March 2026."; "Slash dates are always read day first, even when both numbers are 12 or less: `03/04/2026` is 3 April 2026."; "Spaces before or after the date are ignored."; "The imported date (`Invoice.issued`) is a `datetime.date`" | the three spellings give 2026-03-07; `03/04/2026` gives 3 April; `12/11/2026` gives 12 November; ` 31/12/2026 ` gives 31 December; every value is exactly `datetime.date` |
| `test_iso_dates_are_still_accepted` | Format 1 "`YYYY-MM-DD`, as today" and the spaces sentence | `2026-03-07` and ` 2026-12-31 ` import |
| `test_two_digit_year_is_ambiguous` | "A rejected date raises `ledger.CsvFormatError` ... The message starts with `line N:` ... (the header row is line 1), and contains the date exactly as it appears in the file." and "A slash date with a two-digit year, such as `07/03/26`, is ambiguous ... Its message contains the word `ambiguous`." | `07/03/26` on line 3: CsvFormatError, message starts `line 3:`, contains `ambiguous` and `07/03/26` |
| `test_month_first_slash_date_is_invalid` | "... `03/15/2026` (there is no month 15; slash dates are never read month first) ..." with the `line N:` / value sentence and "its message contains `invalid date`" | `03/15/2026` on line 2: message starts `line 2:`, contains `invalid date` and the value |
| `test_malformed_and_impossible_dates_are_invalid` | "Every other date that is not in one of the two formats, or that names a day that does not exist, is invalid ... This includes `31/04/2026` and `29/02/2025` ..., `2026/03/07`, `07-03-2026`, `7.3.2026` and `2026-3-7`." and the `line N:` / value sentence | each listed value plus `2026-02-30` (a day that does not exist, format 1) gives `line 2:`, `invalid date`, the value |
| `test_same_date_in_both_formats_agrees` | "The same date written in the other format counts as the same date: `2026-03-07` on one row and `07/03/2026` on a later row of the same invoice are accepted." and "The date of an invoice still comes from its first row" | ISO first row with slash later rows, and slash first row with ISO later row, both import with all lines |
| `test_different_date_on_later_row_still_conflicts` | "A later row with a different date is still rejected with `CsvFormatError`, reported on that row's line." | `2026-03-07` then `08/03/2026` for one invoice: message starts `line 3:` |
| `test_cli_exports_iso_dates_and_rejects_ambiguous_ones` | "the export keeps writing dates as `YYYY-MM-DD` whichever format the input used." and "A rejected date raises `ledger.CsvFormatError` (so the CLI exits with status 1)." | `export` JSON dates are `2026-03-09` (from `9/3/2026`) and `2026-03-10`; `09/03/26` exits 1 |
